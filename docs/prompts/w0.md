# W0: core contracts (single session, branch `w0`)

Read `docs/prompts/_session_rules.md` first and follow it, **except** these
points, because W0 is a single session that sets up everything else:

- You may edit any file that this prompt lists.
- You may edit `docs/specification_linter.md`, `CLAUDE.md`, `CHANGELOG.md`
  and `Cargo.toml`.

No other session runs during W0. Everything the parallel waves need to avoid
conflicts is created here, so be precise.

## Step 0: ask the user one question

Ask: **"What is the tool's final name?"** (binary, config file
`<name>.toml`, rules folder `.<name>/`, ignore prefix `<name>-ignore`).

- If they keep `gdguard`, continue.
- Otherwise, replace `gdguard` in `docs/`, `CLAUDE.md` and everything you
  create.
- Don't rename the Cargo package or binary yet. That happens in W8.

## Tasks

1. **Dependencies:** add `serde` (derive feature), `serde_json`, `toml` and
   `globset`, pinned with `=` like the existing ones.
2. **`src/linter/diagnostic.rs`:** every type in the spec's "Shared
   contracts" section (`Position`, `Span`, `Severity`, `FixSafety`, `Edit`,
   `Fix`, `Diagnostic`, `RuleMeta`, `RuleOrigin`, `FileContext`,
   `RuleProvider`) and a full `apply_edits`.
   - Unit tests for `apply_edits`: empty edits, an insert, a delete, multiple
     edits out of order, overlapping edits (error), an edit at the end of the
     file, UTF-8 multi-byte text.
   - Add a helper `Span::from_node(node: &tree_sitter::Node) -> Span`.
3. **`src/linter/api.rs`:**
   - a `Config` struct with every field the spec's config section needs
     (rule levels and options map, custom rule paths, excludes, baseline
     path, overrides, `max_line_length`, `indent_size`);
   - `ConfigError`, `LintResult`, `FixResult`;
   - `load_config_for`, `lint_source` and `fix_source` with their final
     signatures and bodies that return `Err("not implemented yet".into())`.
     Don't use `todo!()`, so callers don't panic.
   - `Config` must be easy to build by hand in tests: derive `Default` and
     make all fields `pub`.
4. **Empty modules** for the W1 to W4 files, with a one-line `//!` doc
   comment saying the owner and purpose:
   - A: `src/linter/config.rs`, `fix.rs`, `baseline.rs`, `cache.rs`,
     `output/mod.rs`
   - B: `src/linter/custom/mod.rs` (with
     `pub fn load_providers(config: &Config) -> Result<Vec<Box<dyn RuleProvider>>, String>`
     returning `Ok(Vec::new())`), `rule_tester.rs`, `explain.rs`,
     `rules_meta.rs`, `init.rs`
   - Wire every `mod` line now, so no later wave needs to touch a parent
     module file.
5. **`src/cli.rs` and `src/main.rs`:** parse **every** flag and subcommand
   from the spec's CLI section. Unimplemented ones print
   "`<flag>` is not implemented yet" and exit 2.
   - `explain`, `test-rules` and `init` call `explain::run`,
     `rule_tester::run` and `init::run`. Each takes the parsed args and
     returns an exit code.
   - `lint --list-rules [--format text|json]` calls
     `explain::list_rules(format) -> i32`, so Track B can implement it
     without touching the CLI.
   - Keep every existing formatter and lint flag working exactly as before.
6. **E2E harness**, owned by the merge session from now on:
   - `tests/e2e/sample_project/`: a minimal Godot 4 project (`project.godot`
     with one autoload, 4 or 5 scripts). It must contain at least one issue
     for several built-in rules, plus code that the planned starter rules
     (`prefer-is-empty`, `no-get-node-in-process`) will flag later.
   - `tests/e2e_tests.rs`: runs the built binary on the sample project and
     snapshots the current output. Add a comment saying later waves extend
     it.
7. **`docs/handoff/`:** create it with a `README.md` explaining that each
   session writes `<branch>.md` there.
8. **`.gitignore`:** ignore `.gdguard/cache/` (use the chosen name).

## Acceptance

- Every existing test still passes, and the formatter and linter output are
  unchanged.
- New tests for `apply_edits` and the CLI stubs (exit code 2 and the
  message) pass.
- `cargo clippy --workspace --all-targets -- -D warnings` is clean.
- `docs/handoff/w0.md` is written using the template. Its "Public API added"
  section lists every contract signature exactly.

When you're done, finish as `docs/prompts/START.md` step 1b says. Also record
the chosen name at the top of `docs/handoff/w0.md` (`Tool name: <name>`), so
later waves use it without asking.
