## Decisions
- **gdextension clippy fix.** `cargo clippy --workspace --all-targets -- -D
  warnings` already failed on `main` with the current toolchain (Rust 1.99):
  15 `semicolon_in_expressions_from_macros` errors and one
  `redundant_field_names` from the `GodotClass` derive. No wave could pass its
  gate, so W0 fixed it in a separate commit (`fa52a4b`) with no behavior
  change.
- **`Config.max_line_length` and `indent_size` are `Option<usize>`.** The
  prompt asks for `derive(Default)`, which would give `0`. `None` means "not
  set in `gdguard.toml`", which is also what the precedence chain needs
  (config, then `.editorconfig`, then the defaults 100 and 4).
- **`Config` has a `config_path` field.** Relative globs in `exclude` and
  `overrides.files` need a base folder.
- **`RuleSetting.options` is a `toml::Table`.** Options come from TOML; JS
  rules can convert it to JSON for `context.options`.
- **Maps are `BTreeMap`.** Stable order for output and the W4 config hash.
- **`ConfigError` is a struct** with optional `path` and `key`, so the spec's
  "errors name the file and the key" is built in.
- **Extra helpers** in `diagnostic.rs`: `Position::from_byte`,
  `Span::from_byte_range` (for text-based rules and fix templates, so W1-A
  and W1-B don't each write one), `Severity`/`FixSafety` `as_str` and
  `from_name`.
- **`apply_edits` ordering:** sort by `(start_byte, end_byte)`, stable. An
  insertion at the start of a replaced range goes first; insertions at the
  same position keep their input order. Touching edits are allowed; an edit
  starting before the previous one ends is an overlap error.
- **Subcommand args are structs in B's modules** (`ExplainArgs`,
  `TestRulesArgs`, `InitArgs`). The CLI is in the binary crate and the
  commands are in the library, so the library can't take the CLI's types.
  The functions take `&Args` (clippy's `needless_pass_by_value` is on).
- **`init --force`** is parsed now because W3-B needs it and B never edits the
  CLI.
- **`--list-rules --format`** accepts `text` or `json` only; plain `lint
  --format` accepts the five reporter names. Any other value is a usage
  error (exit 2).
- **`--list-rules` text output is unchanged.** `explain::list_rules(Text)`
  prints the same lines `main.rs` used to print, so the existing flag keeps
  working until W3-B replaces it.
- **`lsp` stub lives in `main.rs`** (`exit_not_implemented("lsp")`), because
  the LSP is Track A's (W7) and there is no `src/lsp/` yet.
- **Subcommand names now win over file names.** `gdscript-formatter explain`,
  `test-rules`, `init` and `lsp` as the first argument select the subcommand,
  like `lint` already did. A folder with one of those names can still be
  formatted with `./init` or `-- init`.
- **E2E sample project has its own `.editorconfig` with `root = true`**, so
  the repository's settings never change the snapshots. All its scripts are
  formatted (a test checks this) because W3's fix engine only reformats
  already-formatted files.
