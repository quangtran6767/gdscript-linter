# W9 handoff: stronger built-in rules (solo, 2026-11-09)

## Summary

The maintainer tested W8 against Godot 4.7.2 and asked for stronger built-in
rules, plus two project conventions: `load`/`preload` use `uid://`, and
every script has a `class_name` unless it is an autoload. Findings that
drove the list (verified with `godot --headless --check-only`):

- Godot reports `yield`, Godot 3 `connect`, duplicate dictionary keys,
  missing `preload` files and type errors, but not missing `load()` files,
  `x = x`, unreachable code (warning only, not printed headless), duplicate
  `class_name`s, or scene connections to missing methods (silent until the
  signal fires).
- gdguard exited 2 with no JSON when two scripts shared a `class_name`, and
  `unused-private-function` flagged methods connected only in `.tscn` files
  (its suggestion fix would delete them).

## Decisions

- The Godot path is a CLI flag/environment variable, not a `gdguard.toml`
  key: it differs per machine, and the config schema stays unchanged.
- The Godot check imports only when `.godot/global_script_class_cache.cfg`
  differs from the project's `class_name`s: a stale cache gave false
  "Could not find type" errors; `--import` costs ~2.5 s, a check ~0.2 s.
- `prefer-uid-path` reports only paths with a known UID, so every report
  has a safe fix. Godot 4.7 doesn't assign UIDs to `.tscn`/`.tres` files
  on a headless import (only on save), nor to JSON/text files.
- `scene-connection-missing-method` can't see engine methods; it reports
  `_`-prefixed non-virtual methods on engine-based scripts, and any method
  on scripts whose chain has no engine class.
- `self-assignment` skips members: `property = property` re-runs setters.
- `missing-class-name` needs a project (autoload info) and offers no fix
  when the name would hide an engine class (list from Godot 4.7.2
  `--dump-extension-api`, 1074 names), a project class or an autoload.
- Severities: errors for what fails at load or run time
  (`duplicate-class-name`, `scene-connection-missing-method`,
  `missing-resource-path`, `duplicate-dictionary-key`, `godot3-syntax`,
  `godot-error`); warnings otherwise. Naming-rule severities are unchanged.

## Known issues

- Matching scene connections to `unused-private-function` is by name, so a
  connected name in one scene hides an unused method of the same name
  elsewhere (conservative, like `unused-signal`).
- `godot-error` ignores inline ignore comments and the lint cache.
- The Godot check may write `.godot/` and `.uid` files, like the editor.
