## Part A: `[fix] format = true`

- `gdguard.toml` gains a `[fix]` table with one key, `format` (bool,
  default false). Unknown keys and non-bool values are config errors (exit
  2), like other sections.
- With it on, the fix engine's step 5 formats every checked file (even with
  no applied fix, even if it wasn't formatted before), with EditorConfig
  settings and the formatter's structure check (`safe = true`). The
  formatter runs until the text stops changing (at most 3 runs): an inline
  annotation on a local variable (`@warning_ignore("x") var a := 1` in a
  function body) needs two formatter runs to settle, which made a second
  `--fix` run change the file again. Off: behavior is unchanged.
- Summary line: `Fixed N problems in M files, formatted K files` (suffix
  only when K > 0). M now counts files with at least one applied fix, which
  equals the old count when `[fix].format` is off.
- `gdguard init` writes a commented `[fix]` / `# format = true` block.

Decision: a baseline already doesn't stop fixes (`--fix` applies safe fixes
of baselined issues); verified and documented rather than changed. Because
fingerprints use the trimmed line text, reformatting a baselined line
reveals its issue again; docs say to format before `--update-baseline`.

## Part B: `--format agent`

Short text for agents (spec: "AI agent integration"). Per issue the compact
line, `  > <source line>` (120 chars max), `  help: ...`, one line per fix
(`safe fix:` / `unsafe fix:` / `suggestion:` + description); then a summary
line with counts, baseline-hidden count and `gdguard explain <rule>`, and
one hint line each for safe and unsafe fixes. Clean report: no output.

The hook `integrations/claude-code/hooks/lint-gd.sh` now runs
`lint --fix --format agent`. `GDGUARD_HOOK_FORMAT=json` restores the JSON
report; any other value is a tool error (exit 2). First line on issues:
`gdguard: safe fixes are applied; these issues remain. Fix them and lint again.`

## Part C: base rules and `[fix] unsafe`

Codex (`gpt-6.1-sol`, high, read-only) audited mark-my-spell's 750 scripts
and its AGENTS/skills and proposed five rules; Claude implemented them. The
maintainer asked for every rule to be auto-fixable. Rules whose fix can
change behavior keep an honest Unsafe label, and the new `[fix] unsafe =
true | [ids]` lets a project have `--fix` (and the hook) apply them.

| Rule | Level | Fix | mark-my-spell hits |
| --- | --- | --- | --- |
| `single-line-container-type` | error | safe | 0 |
| `prefer-is-empty-call` | info | safe | 3 |
| `prefer-squared-distance` | warning | unsafe | 0 |
| `prefer-array-method` | info | unsafe | 11 |
| `prefer-unique-node-name` | info | unsafe | 5 |

Decisions:

- Id `prefer-is-empty-call`, not `prefer-is-empty`: that id is the example
  custom rule in `gdguard init`, ~30 fixtures and user projects. Projects
  with the example rule get two reports for typed `len(x) == 0`; both fixes
  are safe and identical, so `--fix` clears both.
- Codex proposed Suggestion for rules 3–5 and opt-in for 4–5. They are
  Unsafe (applied with `--fix-unsafe` or `[fix].unsafe`) and on by default;
  4 and 5 are info, which never fails a run or wakes the hook.
- `prefer-squared-distance` accepts `position`/`global_position` and chains
  ending in them (Codex's spec excluded them); the fix is Unsafe anyway.
- `prefer-array-method` drops Codex's "final return" requirement for the
  accumulator (the empty `var` right before the loop is what matters) and
  negates `all` conditions with De Morgan, never flipping `<`/`>=` (NaN).
- Cache version 7: same package version, new rules.
- Project-only conventions (Groups, TweenUtils, AudioManager, EnemyManager,
  glyph enum, owned unique nodes) stay as draft YAML in Codex's scratch
  output; not installed in mark-my-spell.
